# TV Mode v3 — Unattended, Live and Configurable per Screen

Builds on `docs/superpowers/specs/2026-10-31-tv-mode-v2-design.md` and
`docs/superpowers/specs/2026-10-30-tv-mode-design.md`. Everything there still holds unless this replaces it.

## Intent

The TV wall and dashboards now look right; v3 makes them trustworthy on a lobby screen that nobody touches
for weeks, and more useful to the people walking past. A screen must never silently show yesterday's news
or an old version of the site; breaking stories must show up within a minute, not at the end of a round;
people who want to read more can scan a code; one screen can show news and numbers together; and each TV
can be set up from its link alone.

## Goals (owner decided)

1. **Stale-data indicator** on TV and dashboard screens.
2. **Automatic reload** for new versions of the site, plus a nightly reload.
3. **Fix the extra step back** when leaving TV mode (the parked v1 issue).
4. **Breaking news** jumps the queue.
5. **QR codes** on news tiles, on/off in Settings.
6. **Mixed mode**: Latest news with the Vulns dashboard numbers mixed in.
7. **Ransomware world map** panel on the ransomware dashboard.
8. **TV settings in the link**, per screen.

## Non-goals

- No server, push channel or remote control; everything runs in the browser on the static site.
- No new data sources: the map uses victim countries already in the leak-site data.
- No per-tile interaction (tiles stay non-clickable; the QR code is the way to "open" a story).

## Anti-goals

- A reload or version check that interrupts a swap, flashes white, or leaves the screen blank.
- A reload loop (e.g. the new version keeps looking "new").
- A QR code too small or too low-contrast to scan from a few metres, or covering the headline.
- Breaking news that floods the wall (every new story treated as breaking).
- The normal app (not in TV mode) getting bigger or slower.

## 1. Stale-data indicator *(thresholds are my call, owner agreed)*

- A small "Updated 14:05" next to the page counter (bottom-right, same small, dim style) on the TV wall,
  mixed mode and both dashboards.
- The time is when the screen's data was last refreshed (the newer of the app's last successful refresh
  and the snapshot build time).
- After **1 hour** without fresh data it turns **amber**; after **3 hours** **red** with "Data may be
  out of date".
- It updates itself at least once a minute.

## 2. Automatic reload *(my call, owner agreed)*

- While a TV or dashboard screen is open, check every **30 minutes** whether a new version of the site is
  deployed (compare the deployed page's build identity with the running one; a static fetch of the site's
  own files, cache-bypassed).
- When a new version is found, reload at the next quiet moment: right after a swap has landed (never
  mid-animation). If nothing swaps within 2 minutes, reload anyway.
- Also reload once every night at **03:00** local time (same quiet-moment rule).
- A reload keeps the same URL, so the screen comes back in the same mode with the same link settings.
- Guard against loops: never reload more than once per 10 minutes, and never for the same build twice.
- If the check fails (offline), do nothing; the stale indicator covers that case.

## 3. Extra step back

Leaving TV mode with × or Esc while in real full screen can occasionally go back one page too far
(`exitTv` runs history.back() and the full-screen change can trigger a second exit). Fix: leaving runs at
most once per TV session.

## 4. Breaking news (owner decided)

- A story is **breaking** when it arrives while the TV is running (not in the data when the wall started
  or last rebuilt), is **less than an hour old**, and is **critical severity** or about a CVE **newly
  added to CISA KEV**.
- It takes the **next tile that is due to change**, as a **big tile** (the largest shape the grid allows
  at that spot, at least 2×1) with a **red "NEW" badge**.
- The badge stays for **one round**; the story is then an ordinary story.
- Applies to the walls that show news: Latest, Briefing, Ransomware, and mixed mode.
- *(my call)* At most one breaking story arrives per swap; several queue up in order.

## 5. QR codes (owner decided: on/off in Settings)

- Setting "QR codes on tiles", default **off** *(my call)*.
- A QR code in the bottom-right corner of **wide and big news tiles** (2×1 and 2×2), linking to the
  article URL. Single squares get none (too small to scan reliably).
- Dark modules on a white quiet zone so phones read it on the dark theme; sized to scan from about 2–3 m
  on a typical lobby TV *(builder sets the exact size; the headline and summary must never be covered —
  the summary's whole-line fit accounts for the code)*.
- Not on victim/trend tiles without a URL, not on dashboard panels.
- Uses a small QR library (owner approved), loaded only in TV mode.

## 6. Mixed mode (owner decided)

- Latest news with the Vulns dashboard **numbers** mixed in: Critical CVEs 7 d, Added to KEV 7 d,
  Public exploits 7 d, Patch Tuesday — each a single-square number panel that counts up on arrival
  (same component and animations as the dashboard).
- About **one in four** tiles is a number *(my call)*.
- Entry: link `#/latest?tv=1&mix=1`, and a way to start it from the Latest page next to the TV button
  *(builder's call on the exact control; e.g. a small menu on the TV button)*.
- Same page counter, stale indicator, breaking news and QR rules as the news wall.

## 7. Ransomware world map (owner decided)

- A wide (2×1, or 2×2 on Large) panel "Victims by country · 7 days" on the ransomware dashboard pool:
  a world map with countries shaded by victim count (ransomware purple scale), plus the top 3 countries
  as text.
- Countries with no victims stay neutral dark grey; no data at all → panel skipped (existing rule).
- The map outline comes from a static world-countries file (owner approved, about 60–100 KB), loaded
  only when the panel first appears, drawn as SVG with no runtime map library *(my call: shapes are
  prepared once, e.g. pre-projected paths keyed by ISO country code)*.
- Arrival animation: countries fade in by shade, scaled by the animation-speed setting; reduce motion →
  shown at once.

## 8. TV settings in the link (my call on names, owner agreed)

- Params on the TV/dashboard link: `size=large|medium|small|xsmall`, `speed=slow|medium|fast`,
  `transition=fade|slide|reveal`, `interval=<seconds>` (snapped to the 30 s steps), `qr=1|0`, `mix=1`.
- They apply to **that screen only** and never change saved settings; missing or invalid values fall back
  to the saved setting.
- They survive the automatic reload (same URL).

## Settled after the builder check (my calls unless noted)

- **Fresh data:** the app's existing background refresh keeps running while a TV screen is open (it is what
  v1/v2 rely on), so new stories reach the wall without a new refresh loop.
- **"Arrives while running":** the story's id was not in the wall's data when the wall started or last
  rebuilt. **"Newly added to KEV":** the story mentions a CVE whose KEV `dateAdded` is within the last
  24 hours (Briefing's own KEV tiles count when their `dateAdded` is within 24 hours).
- **Victims are never breaking**; only news stories (and Briefing's KEV tiles). A breaking story may
  appear on any news wall where it would normally be listed; it is not added to a wall that would not
  show it.
- **Breaking takes the next due tile whatever it holds** (story or number panel).
- **Map data:** `LeakSiteVictim.country` is an ISO 3166-1 alpha-2 code. The outline comes from Natural
  Earth (public domain) at 1:110m, e.g. via the world-atlas package at build time, converted once into a
  static file of pre-projected SVG paths keyed by ISO alpha-2. Codes with no shape are ignored on the map
  but still count in the top-3 list.
- **Build identity / snapshot time:** the built site already uses content-hashed asset names, so the
  version check compares the main script name in a freshly fetched `index.html` with the running one.
  The snapshot build time is already available to the client (`snapshotGeneratedAt`).
- **Mixed mode:** number panels join the wall's queue like stories (so they count in the pages). If the
  Vulns data is missing, the wall is plain news. `mix=1` only applies on Latest; elsewhere it is ignored.
- **Link params** stay in effect for the whole screen session (Settings is not reachable in TV mode);
  they win over saved settings until the screen leaves TV mode.
- **Reload guard** survives the reload itself (kept in session storage), so "once per 10 minutes, never
  twice for the same build" holds across reloads.
- **Stale indicator placement:** both dashboards already show the page counter; the indicator sits next
  to it everywhere.

## Constraints

- Lazy TV chunk; the main bundle grows only by the settings UI and the TV button control.
- New dependencies limited to the approved small QR library; the map is a static data file.
- Animations follow the speed setting and reduce motion like everything else in TV mode.
- Existing tests keep passing; new pure logic (breaking detection, link params, reload scheduling,
  staleness levels) is unit-tested.

## Left to the builder

- How the version check identifies a build, and how the "quiet moment" is signalled from the wall.
- The exact QR size/placement and the map file format and projection.
- How breaking stories are injected into the engine's queue (as long as they take the next due tile).
- The mixed-mode control on the Latest page.

## Calls I made (owner can override)

- Stale thresholds 1 h amber / 3 h red; version check every 30 min; nightly reload at 03:00.
- At most one breaking story per swap.
- QR off by default; only on wide and big tiles.
- One in four tiles is a number in mixed mode.
- Link param names as above; they never change saved settings.
- Map drawn from pre-prepared shapes, no map library at runtime.
