# TV Mode v2 (Living Tiles) + Categories in Use — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** TV wall and dashboards whose tiles swap one at a time on jittered timers, in three sizes, with
wide↔single morphing, a page counter and animated dashboard panels; plus an app-wide "categories in use"
setting.

**Architecture:** A pure, deterministic tile engine (`src/services/tv/tileEngine.ts`: grid shapes,
tilings, swap planning, pages, counter; randomness and time injected) drives both the TV wall and the
dashboards through one React hook (`useLivingWall`) that owns the timers and the out/in animation phases.
Tiles are placed with explicit grid coordinates, so a swap never reflows the grid. Dashboards become pools
of panel definitions fed to the same engine. Categories are dropped once, where FeedContext exposes
articles.

**Tech Stack:** React 18, TypeScript, Vite, Tailwind, Vitest; no new libraries.

**Spec:** `docs/superpowers/specs/2026-10-31-tv-mode-v2-design.md` (builds on
`docs/superpowers/specs/2026-10-30-tv-mode-design.md`).

## Global Constraints

- No new dependencies; charts are SVG in `src/components/tv/`; animation via CSS / `requestAnimationFrame`.
- TV code stays in the lazy TvShell chunk; the main bundle grows only by settings/category code.
- Animate `opacity`/`transform` only (no layout animation); grid placement is explicit `gridRow`/`gridColumn`.
- Sizes: Large = 3×2 grid, 3–5 tiles; Medium = 4×2, 5–7 tiles; Small = 4×3, 6–10 tiles. Default **Medium**.
- Interval: 30–300 s in 30 s steps, default **60 s**. Jitter = `min(20 s, interval − 20 s)` either way.
- A single merges with a neighbour only if the neighbour has been on screen ≥ 20 s.
- Reduce motion (app setting or OS, via `useReducedMotion` from `../Common/SidePanel`) → 200 ms plain
  fade, count-ups/bars/lines show final values at once.
- Meaning colours stay (critical `#ef4444`, KEV `#fb923c`, exploit `#fbbf24`, ransomware `#a855f7`); no
  colour setting.
- Dark TV theme, entry/exit, wake lock, × behaviour: unchanged from v1.
- Every test command: `npx vitest run <path>`; whole suite `npx vitest run`; types `npx tsc --noEmit`.

## Rulings made while planning (spec amendments)

- **Large needs a 2×2 tile.** With only 1×1 and 2×1 on a 3-column grid, each row holds at most one wide
  tile, so Large can never show 3 tiles (owner's range is 3–5). Large therefore also allows a **2×2 hero**
  (stories and charts/lists, never number panels). Swaps generalise: a tile splits into two halves
  (2×1 → two 1×1 side by side; 2×2 → two 2×1 stacked) and two equal neighbours merge (two 1×1 in a row →
  2×1; two 2×1 stacked in the same columns → 2×2). Medium and Small use 1×1 and 2×1 only.
- **Fewer items than the size's minimum** (e.g. 2 stories): fallback layout, items split the grid into
  equal full-height columns (1 item = whole screen); only same-item re-arrivals happen until data grows.
- **Pages:** page length = ideal count per size (Large 4, Medium 6, Small 8).

## Review Focus

1. Long unattended runs: hours of swaps must not accumulate timers, leave tiles stuck in the out phase, or
   leave a cell uncovered — engine invariant test runs 2,000 random swaps per size (Task 3).
2. Tab hidden for minutes then shown: tiles must not all fire at once — due times shift by the hidden
   duration (Task 4).
3. Data arriving after the wall is up (stories at 0 then 40): the wall fills at once rather than waiting
   for the first timer — signature rebuild test (Task 4).
4. A pool whose items fit badly (dashboard with only wide panels, or only numbers) must never stall: the
   due tile re-arrives itself — engine test (Task 3).
5. Turning off every category but one, then the last one: the UI refuses the last; bookmarks from off
   categories still show in Bookmarks (Task 2).

### Task 3: Tile engine (pure)

**Files:**
- Create: `src/services/tv/tileEngine.ts`, `src/services/tv/tileEngine.test.ts`

**Interfaces:**
- Consumes: `TvTileSize` (Task 1).
- Produces (all exported from `tileEngine.ts`):
```ts
export type Shape = '1x1' | '2x1' | '2x2';            // width x height in cells
export interface GridSpec { cols: number; rows: number; min: number; max: number; ideal: number; shapes: Shape[] }
export const GRIDS: Record<TvTileSize, GridSpec>;      // large {3,2,3,5,4,[1x1,2x1,2x2]}, medium {4,2,5,7,6,[1x1,2x1]}, small {4,3,6,10,8,[1x1,2x1]}
export interface EngineItem { id: string; weight: number; shapes: Shape[] } // stories: all shapes; number panels ['1x1']; charts/lists ['2x1','2x2']
export interface Slot {
  key: string;            // unique per arrival (e.g. `${itemId}#${seq}`); React key
  itemId: string;
  col: number; row: number; w: 1 | 2 | 3 | 4; h: 1 | 2 | 3;   // 0-based origin; fallback layout may use w>2 / h=rows
  cycle: number; page: number; pageCount: number;
  arrivedAt: number; dueAt: number;
  order: number;          // position within the arrival batch, for staggered reveal
}
export interface WallState {
  size: TvTileSize; fallback: boolean;
  queue: { item: EngineItem; page: number }[]; cursor: number; // next unused queue position
  cycle: number; pageCount: number; seq: number;
  slots: Slot[];
}
export interface Swap { leaving: string[]; arriving: Slot[] }   // slot keys; arriving cover exactly the leaving cells
export type Rng = () => number;                                   // [0,1)

export function jitterMs(intervalMs: number): number;            // min(20000, intervalMs - 20000), floored at 0
export function drawDue(now: number, intervalMs: number, rng: Rng): number;
export function initWall(items: EngineItem[], size: TvTileSize, now: number, intervalMs: number, rng: Rng, cycle?: number): WallState;
export function nextDue(state: WallState): Slot | undefined;     // earliest dueAt
export function planSwap(state: WallState, slotKey: string, now: number, intervalMs: number, rng: Rng): Swap;
export function applySwap(state: WallState, swap: Swap): WallState;
export function refill(state: WallState, items: EngineItem[]): WallState; // new cycle: queue rebuilt, slots kept
export function shiftDue(state: WallState, ms: number): WallState;
export function pageLabel(state: WallState): { page: number; of: number } | null; // 1-based; null when no slots
```
- `initWall`: pages = queue split into chunks of `ideal`; enumerate all tilings of the grid with `shapes`
  (recursive fill of the first empty cell; at most a few hundred), keep those with tile count in `[min,max]`, try them
  in order of |count − ideal| (random among equals) and take the first where every rect gets a distinct item that
  allows its shape; larger rects pick the heaviest of the next 3 fitting queue items, 1×1 rects the first fitting one.
  If items < min or no tiling succeeds → `fallback: true`, `min(items, cols)` equal full-height columns.
- `planSwap` ops for the due slot, chosen with `rng` among those that are possible: **replace** (same rect), **split**
  (needs count+1 ≤ max and two fitting items), **merge** (with an equal-shape neighbour that forms an allowed shape,
  arrived ≥ 20 s ago and not leaving, count−1 ≥ min, one fitting item). Weights: replace 0.5, split 0.25, merge 0.25,
  renormalised over the possible ones. Items on screen (other than the leaving ones) are never chosen; items are taken
  from the queue from `cursor` onward (skipped items stay for later). When the queue has nothing fitting, the leaving
  item re-arrives in the same rect. In fallback mode only same-item re-arrival happens.
- `pageLabel`: the slot with the lowest `(cycle, page)` gives `{ page: page + 1, of: pageCount }`.

  - `jitterMs(60000)` = 20000; `jitterMs(30000)` = 10000; `jitterMs(300000)` = 20000.
  - `drawDue(0, 60000, () => 0)` = 40000; `(() => 0.999999)` ≈ 80000.
  - For each size, `initWall` with 30 story items: every cell covered exactly once; count within `[min,max]`;
    all slot items distinct; all on page 0; `pageLabel` → `{ page: 1, of: ceil(30/ideal) }`.

  - **Invariant soak:** per size, 2,000 iterations of `nextDue` → `planSwap` → `applySwap` (now advanced to the due time,

    count stays in `[min,max]`, no item appears twice, every `dueAt - arrivedAt` lies within interval ± jitter, and

```ts
export const SWAP_OUT_MS = 450;           // reduced motion: 200
export function useLivingWall(
  build: () => EngineItem[], size: TvTileSize, intervalMs: number,
  opts?: { signature?: string | number; outMs?: number; now?: () => number; rng?: Rng }
): { slots: Slot[]; leaving: Set<string>; label: { page: number; of: number } | null; fallback: boolean };
```
- Behaviour: one `setTimeout` at a time, armed for `nextDue` (non-leaving slots). On fire: `planSwap`, publish

  is empty/fallback. `visibilitychange` hidden → clear timer and remember the time; visible → `shiftDue` by the
  hidden duration, then re-arm. Unmount clears everything.
