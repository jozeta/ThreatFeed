# Published RSS Feeds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The 30-minute snapshot job publishes three RSS 2.0 feeds (news, vulnerabilities, ransomware). Each item links into ThreatFeed, and the app opens those links on the right story, CVE, Patch Tuesday month or victim.

**Architecture:**
- **Pure feed modules** in `src/services/feeds/`:
  - `rss.ts`: XML and text helpers
  - `links.ts`: deep-link builders
  - `candidates.ts`: what each feed contains
  - `ledger.ts`: what was already published
  - `build.ts`: assembly
- **Wiring:** `scripts/build-snapshot.ts` calls them at the end of its run. It reads the previously published `data/feeds/seen.json` like the other `PREVIOUS_*` files and writes `public/data/feeds/{news,vulns,ransomware}.xml` and `seen.json`.
- **In the app:** a deep-link hook (`?article=`, `?victim=`), a victim highlight, a Subscribe section on the Sources page, and `<link rel="alternate">` tags.

**Tech Stack:** TypeScript, React 18, Vite 8, Vitest 4 (jsdom), tsx for the script. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-03-rss-feeds-design.md`

## Global Constraints

- RSS 2.0 only; no JSON Feed or Atom. Structured values are `<category>` elements.
- Files: `public/data/feeds/news.xml`, `public/data/feeds/vulns.xml`, `public/data/feeds/ransomware.xml`, `public/data/feeds/seen.json`, published as `<site>/data/feeds/…`.
- Window: the last **7 days**, newest first. Caps: **100** (news), **100** (vulns), **400** (ransomware).
- Channel: titles `ThreatFeed — News`, `ThreatFeed — Vulnerabilities`, `ThreatFeed — Ransomware`; `language` `en`; `ttl` `30`; `lastBuildDate`; `atom:link rel="self"`.
- Item kinds (category values): `news`, `kev`, `critical-cve`, `exploit`, `patch-tuesday`, `victim`.
- GUIDs: `news:<article id>`, `kev:<CVE>`, `cve:<CVE>`, `exploit:<CVE>:poc` / `exploit:<CVE>:metasploit`, `pt:<month id>`, `victim:<victim id>`. All are `isPermaLink="false"`.
- Description: plain text, at most **400** characters, ending with `Source: <name> <url>`. All text is escaped for XML, and characters invalid in XML 1.0 are removed. No HTML from sources.
- Critical CVE: CVSS ≥ **9.0**. Exploit items only for CVEs in KEV or with CVSS ≥ 9.0.
- Ledger: per feed, entries pruned **90 days** after they were last seen in the data.
- pubDate is first-seen time. The source timestamp is used instead when it is earlier than first-seen by less than **24 h**. Never in the future.
- Size budgets: news and vulns about 300 KB each, ransomware about 500 KB, `seen.json` about 2 MB. Log a warning when over budget, like the other files.
- Failure: if `seen.json` can't be read (anything but HTTP 404), or feed building throws, the job writes none of the four feed files. The rest of the snapshot still deploys, and the workflow restores the published copies.
- Site URL for absolute links: env `FEED_SITE_URL`, default `https://jozeta.github.io/ThreatFeed/` (trailing slash).
- CLAUDE.md rules: feed HTML is untrusted; static hosting only; add tests next to the code (`*.test.ts`); no new npm dependencies.

## Review Focus

1. **A cluster whose lead article changes between runs.** It must keep its first guid and not be re-announced. Pinned in Task 3: `keeps a news story's guid when its lead article changes`.
2. **The first run after deploy, and a later unreadable ledger.** The first run must not post every existing exploit. An outage must not wipe the history. Pinned in Task 3 (`first run records exploits as baseline`) and Task 4 (the 404 vs other error test).
3. **Titles with `&`, `<`, emoji, Japanese, and control characters such as `\u0001`.** They must produce valid XML. Pinned in Task 1: `escapes and cleans hostile text`.
4. **A CVE that is both new in KEV and critical in the same run, or KEV-listed later.** It must give exactly one item. Pinned in Task 3: `one item per CVE across kev and critical-cve`.
5. **A deep link to a story that is no longer in the visitor's data, or not loaded yet.** The app must wait for the first sync, then show a notice with the original link, never a blank page. Pinned in Task 5: `resolveDeepLink waits for sync, then reports missing`.

### Task 2: Deep links and feed candidates

**Files:**
- Create: `src/services/feeds/links.ts`, `src/services/feeds/candidates.ts`
- Test: `src/services/feeds/links.test.ts`, `src/services/feeds/candidates.test.ts`

**Interfaces:**
- Consumes: `plainText` (Task 1); `clusterArticles` (`src/services/articles/clustering.ts`); the types `Article`, `LeakSiteVictim`, `VulnData`, `KevEntry`, `CveRecord`, `ExploitInfo`, `MsrcData`, `PatchMonth` (`src/types`).
- Produces, in `links.ts` (`site` always ends with `/`):
  - `storyLink(site: string, article: Pick<Article,'id'|'url'>): string` returns `${site}#/latest?article=<enc id>&src=<enc url>`. `src` is left out when the url is empty.
  - `cveLink(site, cve)` returns `${site}#/vulns?cve=<CVE>`.
  - `patchLink(site, monthId)` returns `${site}#/vulns/patch?month=<enc monthId>`.
  - `victimLink(site, v: Pick<LeakSiteVictim,'id'|'group'>)` returns `${site}#/ransomware?victim=<enc id>&group=<enc group.toLowerCase()>`.
- Produces, in `candidates.ts`:
  - `type FeedName = 'news' | 'vulns' | 'ransomware'`
  - `type ItemKind = 'news' | 'kev' | 'critical-cve' | 'exploit' | 'patch-tuesday' | 'victim'`
  - `FeedCandidate`:
    ```ts
    interface FeedCandidate {
      feed: FeedName; guid: string; kind: ItemKind; title: string; description: string; link: string;
      sourceTime?: string;        // real source timestamp, if any
      categories: string[];       // kind first, then CVEs, severity, cvss bucket, group/country/sector
      keys: string[];             // identity keys: 'a:<article id>', 'u:<normalized url>', 'c:<CVE>', 'v:<group>|<name>'
      baseline?: boolean;         // exploits: on the very first run, record without publishing
      rank: number;               // processing order within a run: lower first
    }
    ```
  - `normalizeUrl(url: string): string`: lowercases the host; strips the hash, `utm_*` params and a trailing `/`.
  - `newsCandidates(articles: Article[], now: number, site: string): FeedCandidate[]`
  - `ransomwareCandidates(articles: Article[], victims: LeakSiteVictim[], now: number, site: string): FeedCandidate[]`
  - `vulnCandidates(vulns: VulnData | null, msrc: MsrcData | null, now: number, site: string): FeedCandidate[]`

**Selection rules** (spec "What goes in each feed"; WINDOW = 7 days before `now`):

- **News:**
  - Take articles published within the window and run `clusterArticles` over them.
  - A cluster qualifies when any member has severity `critical` or `high`.
  - The chosen article is the qualifying member with the highest `severityScore`, then the earliest `publishedAt`, then the smallest `id`.
  - guid `news:<id>`; title = the headline.
  - Description: `plainText(description, 300)`, then ` Also covered by N other outlets.` when N > 0, then ` Source: <sourceName> <url>`. Trim the whole thing to 400 characters.
  - keys: every member's `a:<id>` and `u:<normalizeUrl(url)>`.
  - Categories: `['news', severity, ...cves]`. sourceTime = the chosen article's `publishedAt`. rank = 10.
- **Ransomware news:** the same as News, but over articles whose `tags` include `'Ransomware'` (case-insensitive), with **no severity filter**. The feed is `'ransomware'`, and the categories start `['news','ransomware', …]`.
- **Victims:** `discoveredAt` within the window. guid `victim:<id>`.
  - Title: `Victim: <victim> (<group> · <country> · <sector>)`, leaving out missing parts.
  - Description: `plainText(description, 250)` plus `Group: <group>.`, and `Source: ransomware.live <url>` when there is a `url`.
  - keys: `['v:' + group.toLowerCase() + '|' + victim.toLowerCase().replace(/\s+/g,' ').trim()]`.
  - Categories: `['victim', group, country?, sector?]`. sourceTime = `discoveredAt`. rank = 20.
- **KEV:** `dateAdded` within the window (compare as `YYYY-MM-DD` ≥ the window start day).
  - guid `kev:<CVE>`; title `KEV: <vendor> <product> — <CVE>`.
  - Description: `<name>. Added to CISA KEV <dateAdded>; due <dueDate>.`, plus ` CVSS <x>.` and ` EPSS <n>%.` when known, plus ` Known ransomware use.` when `ransomware`, then ` Source: CISA KEV https://www.cisa.gov/known-exploited-vulnerabilities-catalog`.
  - keys `['c:<CVE>']`. Categories: `['kev', CVE, 'cvss-<floor>' when known, 'ransomware' when flagged]`. sourceTime = `dateAdded + 'T00:00:00Z'`. rank = 0.
- **Critical CVE:** `vulns.notable` with `score ≥ 9` and `published` within the window.
  - guid `cve:<CVE>`; title `Critical CVE (<score>): <assigner or 'NVD'> — <CVE>`.
  - Description: `plainText(description, 280)` plus ` CVSS <score>.` plus ` Source: NVD https://nvd.nist.gov/vuln/detail/<CVE>`.
  - keys `['c:<CVE>']`. Categories: `['critical-cve', CVE, 'critical', 'cvss-9']`. sourceTime = `published`. rank = 1.
- **Exploit:** for each CVE in `vulns.exploits` that is in KEV (any `dateAdded`), or in `notable` with score ≥ 9:
  - When `pocs > 0`: guid `exploit:<CVE>:poc`, title `Exploit: <CVE> — public proof of concept`, Source = the first `pocUrls` entry, or `https://github.com/search?q=<CVE>`.
  - When `msf?.length`: guid `exploit:<CVE>:metasploit`, title `Exploit: <CVE> — Metasploit module`, Source `Metasploit https://github.com/rapid7/metasploit-framework`.
  - The description names the product (KEV vendor and product when known) and the count.
  - keys: `['x:<CVE>:<kind>']`. `baseline: true`. No sourceTime. rank = 2.
- **Patch Tuesday:** each `msrc.months` entry with `released` within the window.
  - guid `pt:<month.id>`; title `Patch Tuesday <Month YYYY>: <n> CVEs, <exploited> exploited`. The month name comes from `title` minus ` Security Updates`.
  - Description: counts of critical (`severity === 'Critical'`), exploited and publicly disclosed CVEs, then ` Source: Microsoft MSRC https://msrc.microsoft.com/update-guide`.
  - keys `['p:<month.id>']`. Categories `['patch-tuesday']`. sourceTime = `released`. rank = 3.

### Task 3: Ledger and feed assembly

**Files:**
- Create: `src/services/feeds/ledger.ts`, `src/services/feeds/build.ts`
- Test: `src/services/feeds/ledger.test.ts`, `src/services/feeds/build.test.ts`

**Interfaces:**
- Consumes: Tasks 1 and 2.
- Produces, in `ledger.ts`:
  ```ts
  interface LedgerEntry { firstSeen: string; lastSeen: string; published: boolean; keys: string[] }
  interface FeedLedger { version: 1; feeds: Record<FeedName, Record<string /* guid */, LedgerEntry>> }
  emptyLedger(): FeedLedger
  decodeLedger(raw: unknown): FeedLedger | null      // null for anything malformed; drops malformed entries
  pruneLedger(ledger: FeedLedger, now: number, keepDays = 90): FeedLedger   // drops entries with lastSeen older than keepDays
  pickPubDate(sourceTime: string | undefined, firstSeen: string): string    // spec rule: source time if valid, ≤ firstSeen and < 24 h earlier; else firstSeen
  ```
- Produces, in `build.ts`:
  ```ts
  interface FeedInput { articles: Article[]; victims: LeakSiteVictim[]; vulns: VulnData | null; msrc: MsrcData | null }
  interface FeedBuild { files: Record<FeedName, string>; ledger: FeedLedger; counts: Record<FeedName, number> }
  buildFeeds(input: FeedInput, previous: FeedLedger | null, now: number, site: string): FeedBuild
  FEED_CAPS = { news: 100, vulns: 100, ransomware: 400 }
  ```
  `previous === null` means the first run.

**The assembly algorithm.** Neither the signature nor the tests fully determine it. Run it per feed, over that feed's candidates sorted by `rank`, then `sourceTime` (ascending), then `guid`:

1. Build `keyIndex: key → guid` from the feed's existing entries.
2. For each candidate, look for a match: the candidate's own guid if it is in the ledger, otherwise the first of its `keys` found in `keyIndex`.
   - **Match found:**
     1. Set the matched entry's `lastSeen` to now and merge the candidate's keys into it.
     2. Then render the candidate **under the matched guid**, with the entry's `firstSeen`, but only when all of these hold: the entry is published, its guid has not already been rendered this run, and either the candidate is `kind === 'news'` or the matched guid equals the candidate's guid.
     3. Otherwise, skip it. This suppresses a CVE's second kind and a cluster split into two.
   - **No match:**
     1. If `previous === null` and `candidate.baseline`, record the entry with `published: false` and do not render it.
     2. Otherwise record `published: true` with `firstSeen = lastSeen = now` and render it.
     3. Either way, add its keys to `keyIndex`.
3. Each rendered item's `pubDate = pickPubDate(candidate.sourceTime, entry.firstSeen)`. Keep the items with `pubDate ≥ now − 7 days`, sort by pubDate descending (then guid), and cap at `FEED_CAPS[feed]`.
4. Use `pruneLedger` on the result. Render each feed with `renderRss`. The channel `link` is `site`, `selfUrl` is `${site}data/feeds/<feed>.xml`, and the descriptions are:
   - News: `Important security stories from ThreatFeed, one per story.`
   - Vulnerabilities: `New CISA KEV entries, critical CVEs, public exploits and Patch Tuesday, from ThreatFeed.`
   - Ransomware: `Ransomware leak-site victims and ransomware news, from ThreatFeed.`
