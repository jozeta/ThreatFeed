# TV Mode v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make TV/dashboard screens safe to leave unattended (stale indicator, auto reload, exit fix) and more useful (breaking news, QR codes, mixed mode, ransomware map, per-screen link settings).

**Architecture:** Pure helpers in `src/services/tv/` (link overrides, staleness, reload policy, breaking detection, mixing, map data) with unit tests; thin React glue in `src/components/tv/`. One hook (`useTvSettings`) gives every TV component the effective settings (saved settings overridden by link params). The engine gains one operation (`prioritize`) for breaking stories; `useLivingWall` exposes it and announces "quiet moments" after each landed swap for the reload logic.

**Tech Stack:** React 18, TypeScript, Vite, Vitest. New runtime dep: one small MIT QR library (TV chunk only). New dev deps for a one-off map build script.

**Spec:** `docs/superpowers/specs/2026-10-31-tv-v3-design.md` (builds on the v2 and v1 TV specs).

## Global Constraints

- TV code stays in the lazy TvShell chunk; main bundle grows only by the settings UI and the Header TV control.
- Runtime deps: only the approved QR library. The map is a static file (`public/data/world-map.json`, ≤ 100 KB) built once by a script; no map library at runtime.
- Stale indicator: amber after 1 h, red after 3 h ("Data may be out of date"); updates at least once a minute.
- Reload: check every 30 min; reload at the next quiet moment (right after a swap lands), or after 2 min without one; nightly at 03:00 local; never more than once per 10 min, never twice for the same build (guard kept in sessionStorage).
- Breaking: arrived after the wall started or last rebuilt, < 1 h old, critical severity or mentions a CVE whose KEV `dateAdded` is within 24 h (Briefing's KEV tiles: `dateAdded` within 24 h); victims never; takes the next due tile; at least 2×1 where possible; red "NEW" badge for one round; at most one per swap.
- QR: setting `tvQrCodes`, default off; only on 2×1 and 2×2 news tiles with a URL; never covers headline or summary text.
- Mixed mode: Latest only (`mix=1`); every 4th item is a Vulns number panel (Critical CVEs 7 d, Added to KEV 7 d, Public exploits 7 d, Patch Tuesday); no Vulns data → plain news.
- Link params: `size`, `speed`, `transition`, `interval` (seconds, snapped to 30 s steps), `qr` (1|0), `mix` (1); invalid/missing → saved setting; never written to saved settings.
- All animations follow the speed setting (`--k`) and reduce motion.
- Commands: `npx vitest run <path>`, `npx vitest run`, `npx tsc --noEmit`, `npx vite build`.

## Review Focus

1. The fetched `index.html` is served from cache or has no recognizable main script → never reload (Task 2 test: `mainScriptName` returns null → `shouldReload` false).
2. The first data load after the wall starts brings 30 stories at once → none of them is "breaking" (Task 3 test: ids present at start/rebuild are seen).
3. A laptop/TV asleep past 03:00 wakes up → exactly one nightly reload, not one per check (Task 2 test on `nightlyDue`).
4. A very long article URL → the QR code still renders at the fixed size (Task 4: encode with error correction level L, auto version; test that a 300-char URL encodes).
5. `#/latest?tv=1&size=huge&interval=7` → saved size and nearest valid interval (Task 1 test).

### Task 3: Breaking news

**Files:**
- Create: `src/services/tv/breaking.ts`, `src/services/tv/breaking.test.ts`
- Modify: `src/services/tv/tiles.ts` (TvTile gains `cves?: string[]`, `critical?: boolean`, `url?: string`; `storyTile` fills them from the article; KEV tiles get `cves: [cve]`, `critical: false`), `src/services/tv/tileEngine.ts` (+ tests), `src/components/tv/useLivingWall.ts` (returns `prioritize`), `src/components/tv/TvWall.tsx`, `src/components/tv/TvTileCard.tsx` (badge), `src/index.css` (`.tv-new-badge`: red `#ef4444` pill "NEW")

**Interfaces:**
- Produces: `findBreaking(tiles: TvTile[], seen: Set<string>, kevAdded: Map<string, string>, now: number): TvTile[]` — tiles not in `seen`, `kind !== 'victim'`, `time` < 1 h old, and (`critical` or any of `cves` with `kevAdded` date within 24 h); newest first.
  Engine: `prioritize(state: WallState, item: EngineItem): WallState` — puts `item` at the front of the unused queue with a `priority: true` flag (dropping any older unused copy); `planSwap` takes a priority entry first and prefers the largest allowed shape for it at the due spot: merge with a single neighbour ignoring the 20 s age guard if the due tile is 1×1 and count − 1 ≥ min; otherwise the due tile's own shape. At most one priority item per swap.
  Hook: `useLivingWall(...)` returns `prioritize(items: EngineItem[]): void` (applies the engine op to the live wall state; no re-render needed).
- TvWall: keeps `seen` (all tile ids of the build at start / every full rebuild); on every data change runs `findBreaking`, adds results to `seen`, calls `prioritize`; keeps `breaking: Map<id, cycle>`; a tile shows the badge while `slot.cycle === breaking.get(id)` (one round). `kevAdded` from `vulns.kev` (`cve → dateAdded`) and `cveIntel[cve].kevDateAdded`.

- [ ] Step 1: Failing tests: `findBreaking` — critical 10-min-old unseen → yes; seen → no; 2-h-old → no; victim → no; non-critical with a CVE added to KEV 3 h ago → yes, added 3 days ago → no. Engine — after `prioritize`, the next `planSwap` on a 1×1 due slot with a single neighbour arrived 5 s ago merges into a 2×1 holding the priority item; with count at min it replaces in place; a second `prioritize` before the swap keeps both in order and only one arrives per swap; soak invariants (coverage, distinct items, count range) still hold with a priority item injected every 50 swaps.
- [ ] Step 2: FAIL. Step 3: implement. Step 4: wire TvWall + badge (also a hook test: `prioritize` then advancing to the next due swap shows the item). Step 5: full suite + tsc. Commit `feat(tv): breaking news jumps the queue with a NEW badge`.
